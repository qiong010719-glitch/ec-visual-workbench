# 重复文案恢复修复：1.0.2-duplicate.1

日期：2026-11-15。Windows x64 便携测试版。

## 问题与修复

旧版在两套画面标题重复时会检查并尝试改写，但存在几个无法正常恢复的分支。局部 Markdown 加粗会导致检测到重复却无法定位原文替换；单套内重复会先把构思标记为失败，无法进入批量修正；商品英文标题重复直接报错。页面还可能把重复提示放在实际构思超时之前，使人误以为整个程序因重复卡死。

- 统一标题读取与原文定位。支持局部加粗、标题外部引号，替换仅影响指定画面标题，其余方案保留。
- 同一套和不同套的重复画面标题均进入自动修正。保留一条，改写其余冲突项；已提交图片的方案不能自动覆盖。
- 文案修正最多两轮。仅在完整有效的结果仍重复时进行第二轮；超时、断线、HTTP 错误或格式错误立即保留原方案并显示失败原因，不自动反复提交。
- 商品英文标题重复时，仅重写后续冲突条目，最多两轮。保存已校验的候选标题；失败后点击重试或重启程序继续时，不重做已完成的构思和初始标题请求。
- 页面显示各套构思完成数量、正在执行的套数、失败套数、修正轮次。尚有构思进行时，重复提示说明等待检查；失败后显示实际原因并开放相应重试按钮。
- 新版启动会检查后台修复版本，避免新版窗口误用仍在运行的旧版服务。

这里只检查规范化后的完整标题重复，大小写、标点和全角差异不能绕过检查。商品事实、数字、单位及明确要求共用的文案仍允许复用；没有新增语义近似度拦截。

## 使用

1. 完成或暂停旧版当前任务，关闭旧工作台及旧后台服务。
2. 启动 `Temu-Workbench-1.0.2-duplicate.1-win-x64.exe`。无需另装 Node.js 或 Python。
3. 同一 Windows 账户、同一工作台数据目录下继续使用已有配置和历史任务。新电脑使用自己的连接设置，不复制他人的密钥或测试数据。
4. 打开失败批次，点击“重试失败构思”“重试重复文案修正”或“重试重复商品标题”。准备完成后仍由用户点击生成图片。

两轮有效改写仍重复时，批次会明确进入“需要处理”，保留内容并允许重试，不会绕过质量检查自动生图。此版本是内部未签名测试包，尚未在报告问题的那台实体电脑上验证。
