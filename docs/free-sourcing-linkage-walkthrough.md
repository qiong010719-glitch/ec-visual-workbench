# 工作台与店小秘联动：采集、认领、补全上架

版本：2026-11-22，按用户确认的流程分段及固定上架模板要求修订。本文保留业务设计和此前现场记录；固定模板与批次联动入口已加入程序，使用方法及当前支持范围见[固定模板使用说明](fixed-listing-templates.md)。完整现场检验仍在进行。

选品采集只需选择来源前端平台、输入关键词和数量。认领负责将采集结果分配到各平台采集箱；进入平台采集箱后，再选择要处理的店铺，批量补全商品资料并上架。三个阶段按此顺序衔接；已有程序入口不代表采集箱到平台在售已经全部实测通过。

## 三个业务阶段

| 阶段 | 工作台输入与操作 | 店小秘对应位置 | 阶段结果 |
| --- | --- | --- | --- |
| 1. 选品采集 | 来源前端平台、关键词、采集数量；启动采集 | 前端商品页的采集插件 → 产品 / 通用服务 / 数据采集 | 本批商品对应的通用采集记录 |
| 2. 认领分发 | 选择本批已采集商品；在认领阶段选用分配模板 | 数据采集 → 批量认领 → 认领到采集箱 | 目标平台采集箱中的商品记录 |
| 3. 批量补全与上架 | 本次待处理商品、已保存的上架模板；自动带出适用店铺、站点及填写配置 | 平台采集箱 → 店铺筛选 → 全属性修改 / 批量操作 → 发布 | 各店铺的发布结果、失败原因和待处理项 |

来源平台是去哪里搜索商品，例如Temu前台；目标平台是商品要进入哪个业务采集箱，例如Temu半托管或TikTok。两者单独记录。现有采集实测针对Temu，多来源平台选择是后续界面设计，不代表其他来源已接通。

选品表单不要求选择上架店铺或认领模板。此前提出的店小秘模板联动保留在认领分发阶段，不能作为关键词搜索的前置条件。店小秘账号连接属于连接设置，也不等于选择上架店铺。

认领后的商品记录已经可能带有店铺归属。平台采集箱中的“选择店铺”用于限定本次批量修改与发布范围；不能理解为商品到此时才首次关联店铺。

## 模板分别用于什么

| 名称 | 所在位置与用途 | 使用阶段 |
| --- | --- | --- |
| 认领分配模板，如“画板”“电器” | “选择店铺-认领到采集箱”弹窗右侧；保存人工维护的平台、店铺及站点组合 | 采集后批量认领时，决定商品分配去向 |
| 工作台固定上架模板 | 工作台长期保存商品填写规则、适用店铺及各店配置；当前范围见[使用说明](fixed-listing-templates.md) | 商品认领入箱后，加载已保存配置进行批量补全；不要求每次重新填写 |
| 产品模板、变种模板 | 平台采集箱“批量操作”中的“引用产品模板”“引用变种模板” | 补全商品阶段；覆盖哪些字段及如何应用仍需实走 |
| 运费模板 | 商品运输信息、“全属性修改 → 运费模板” | 按店铺与站点配置运输信息，具体可选项仍需实走 |

“核对模板”应发生在批量认领时：核对实际选中的认领分配模板及其目标集合。产品模板、变种模板、运费模板分别保存和应用，不能用一个“模板”字段混合表示。

## 工作台联动设计

1. **选品采集页**：选择来源平台，输入关键词和数量，产生一个批次。显示已发现商品、采集成功、复用、失败和待核对数量，保留来源链接与商品身份。
2. **认领分发页**：从已采集批次继续，读取店小秘人工维护的认领分配模板，展示其目的平台、店铺和站点。只选择该批次对应记录，提交后按实际目的地记录结果。
3. **批量上架页**：从平台采集箱继续，确定本次商品范围并选择已保存的上架模板，自动加载适用店铺、站点和分类、属性、仓库、运输等配置。正常复用无需重新填写；仅集中处理缺失项或失效配置。记录各项修改是否保存，以及后续发布是否成功。

一个商品应能沿着“采集批次 → 来源商品 → 通用采集记录 → 各平台 / 店铺 / 站点的采集箱记录 → 修改与发布结果”追踪。一个来源商品分配到多店后可能产生多个记录，采集商品数、认领记录数和发布成功数分别统计。

认领模板归属包含店小秘账号；认领阶段保存实际目标集合，提交前与加载完成后的勾选对照。模板发生变化时展示差异，避免静默改变分配去向。后续上架设置按具体平台、店铺、站点维护，不能直接套用另一店的仓库或运费设置。

## 固定上架模板：首次配置，长期复用

用户于2026-11-22确认：商品填写方案和各店差异可以长期保存成固定模板，不应每次执行都重新填写。以下保留已确认的业务设计；保存、版本与重启读回已有隔离验证，当前程序范围和仍需现场核对的部分见[使用说明](fixed-listing-templates.md)。

模板按目标平台及业务类型、销售站点、适用商品类型组织，例如“Temu半托管·加拿大·帆布画”。具体末级分类和属性规则需要继续实走确定，模板名称不能替代真实分类。一个模板可供多店使用，一家店也可关联多个商品模板；仅仓库或运费模板不同，不必复制整套商品填写方案。

| 长期保存的内容 | 保存及复用方式 |
| --- | --- |
| 模板名称和适用范围 | 保存目标平台、业务类型、站点和适用商品类型；按店小秘账号识别店铺绑定 |
| 共用填写规则 | 保存已确认的末级分类、属性填写规则、标题处理及定价规则等；只应用到符合条件的商品 |
| 适用店铺 | 保存模板绑定的店铺集合，下次选模板时默认带出，无需逐店重新勾选 |
| 每家店的配置 | 按店铺及站点保存对应仓库、运费模板、发货时效，以及需要的定价、库存处理规则差异；名称相同也不能替代真实店铺绑定 |

操作设计：

1. **首次配置**：创建模板，填写共用规则，关联店铺并设置各店配置，保存到工作台的持久化配置中。
2. **日常使用**：商品采集并认领入箱后，选择本次商品批次和固定上架模板。工作台加载保存内容，展示适用店铺和配置摘要，按各店对应的采集箱记录执行批量填写。正常批次不再重复填写设置。
3. **范围调整**：本次需要少处理某家店时可以临时取消；临时选择不覆盖固定模板的店铺绑定。模板绑定的店铺在本批次没有对应采集箱记录时，明确提示缺少记录，不自动扩大认领或商品范围。
4. **后续维护**：新增店铺、主动修改规则或平台字段变化导致绑定失效时，只处理发生变化的设置。模板可以修改或复制另存；关闭页面、重启工作台后仍应保留。
5. **修改影响**：模板更新默认用于后续新任务；已创建任务记录当时使用的模板版本及配置，恢复执行时沿用。修改模板本身不修改已有商品或已上架商品，重新应用时需明确商品范围。

固定模板保存的是可复用设置和填写规则，不会把每件商品的尺寸、重量、材质、图片等不同事实强行设成同一值。缺少商品资料或遇到新增必填字段时，将对应商品和缺失项列出；不要求重新填写整个模板，也不凭空补值。

执行仍按平台、店铺、站点和适用商品组逐组完成，只处理本批已对应的商品记录；工作台一次选择模板不代表店小秘已经支持跨店一次保存。固定上架模板与认领分配模板分别维护，选品采集入口仍只要求来源平台、关键词及数量。

模板功能实现后的验收包括：保存后刷新或重启可读回；另一批兼容商品可直接复用；各店绑定分别正确；修改模板不影响进行中任务和既有商品；缺失或失效配置只提示对应待处理项。

## 接着实走采集箱到上架

以下是用户七张截图支持的操作顺序，尚未由助手完成现场批量修改或发布：

1. 在“产品”菜单进入目标平台的采集箱，例如Temu半托管。
2. 在“店铺账号”处选择要处理的店铺，需要时进一步限定站点，并定位本次要处理的商品。截图示例为店铺1共70条、每页50条，勾选当前页显示50条；跨页选择范围需核对，不能把当前页全选当成全部70条。
3. 查看代表商品缺什么，再决定哪些商品可以一起修改。截图直接显示产品分类未选择、仓库未选择、发货时效未选择和运费模板未选择；分类尚未设置时，后续需填哪些产品属性仍待实际展开确认。
4. 通过“全属性修改”设置分类、产品属性、仓库、发货时效、运费模板等。菜单另有SKU、价格、重量、尺寸、库存、标题等功能；功能可见不等于本批所有这些字段都缺失，也不代表可以套用相同值。
5. 需要时通过“批量操作”进行批量编辑、引用产品模板或变种模板。逐项核对其实际影响范围、保存动作和修改结果，确定可以固化的重复步骤。
6. 补全后检查商品的必填项、店铺和站点。保存、移入待发布、直接发布或定时发布的具体路径，随用户后续实走确定。
7. 核对发布结果：提交中、成功、失败分别记录。按平台实际返回结果判断是否上架，失败项保留原因和已完成的修改。

后续实走需要记录真实选用的分类、属性值、仓库、发货时效、运费模板以及批量修改范围，不能从截图推定这些业务值。当前尚未执行该段修改或发布。
