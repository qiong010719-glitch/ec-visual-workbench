# SHEIN 站点绑定与认领修复

2026-11-25，当前维护目录与 4196 工作台。版本 `crossborder-shein-site-20261125-3`。

## 原因

设置页允许保存 SHEIN 的经营站点，但 `directAllocationDestinations` 拒绝所有非空 SHEIN 站点。本次真实任务在进入浏览器前约 12 毫秒即被拦截，没有认领提交记录。

真实只读观察的 SHEIN 采集箱共 6 条记录，列表没有站点列。现有认领弹窗的 SHEIN 目的地按店铺读取，不提供独立站点选择。将配置站点直接与弹窗的空站点比较，会产生规则冲突。

## 处理

- 保留设置和历史任务中的站点，不清空用户填写的“美国站”。
- 只在生成 SHEIN 认领目的地时投影为平台、店铺名称和真实店铺 ID，站点为空。提交前的日志校验使用同一投影，仍严格拒绝店铺 ID 变化、额外目的地或伪造站点选择。
- 提交记录的 `destinations` 保留配置范围，`payload.destinations` 保存真实弹窗观察，二者不混为已选择销售站点的证据。
- SHEIN 列表或编辑页明确不提供站点列/字段时，按来源商品及店铺核对；页面提供站点时，仍校验实际值，空值和冲突值不能放行。TikTok 和 Temu 的站点校验不放宽。
- 列表已找到同源店铺商品但站点不符时，标记待核对，不误报未认领，不重复认领。
- 保存回读和移入待发布沿用同一规则。实际页面站点保存在快照，配置站点与页面观察另行记录。
- 修改 SHEIN 本地站点标签不能绕过同一店铺的未决认领记录。修改真实店铺绑定仍须遵守原任务身份检查。
- 设置页补充说明：SHEIN 认领按店铺，站点用于本地分组和页面有该字段时的核对；不声称通过认领弹窗选择了销售站点。
