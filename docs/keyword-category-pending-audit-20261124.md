# 关键词采集、分类选择与必填补全

更新日期：2026-11-24（北京时间）。用户确认修改后，已在新版跨境工作台实现本流程。源码入口为本目录，服务端口为 4196；旧 4185 工作区未改动，也未合并旧数据、凭据或浏览器登录资料。

## 使用顺序

1. 打开“连接设置 → 采集箱目标店铺”，绑定店小秘账号、平台和完整店铺名称。支持 Temu、SHEIN、TikTok；Temu 要指定站点，其他平台无站点时可留空。这里不要求母稿或固定模板。
2. 在“免费选品”按关键词完成采集及入箱核对。进入“批量补全与上架”，默认方式为“自动补齐必填项，转入待发布”。
3. 选择已确认入箱的本批商品及目标店铺，建立任务，核对采集箱记录。未领取的商品可按后台绑定领取；只处理本批选中商品。
4. 在逐店商品行中点击“选择分类”，从对应店铺的真实目录逐级进入末级分类。可用于当前商品，也可应用到本批同店的同类商品。不同店铺分别读取目录；电动榨汁机、手动榨汁器等不同类型可分别选择。
5. 执行必填补全。程序按当前表单识别必填空项，选择分类后重新检查动态出现的字段，填写、保存并在独立页面回读。
6. 所有目标商品准备完成后，点击“批量转入待发布”。逐件移动并核对来源、店铺、草稿编号和保存内容；全部核对成功后任务显示“已转待发布”。自动补全任务没有正式发布动作，后端也拒绝该动作。

入口：

- 设置：<http://127.0.0.1:4196/settings#collectionStores>
- 批量补全：<http://127.0.0.1:4196/sourcing/listing>
- 旧固定模板：<http://127.0.0.1:4196/sourcing/listing?mode=template>

## 填写规则

- 根据必填标记、当前空值、字段类型、范围、步长和可见校验提示识别要填写的项目，不再只限定包装、重量和库存。
- 数值空项使用符合平台约束的占位值；已有价格、库存、标题等内容保留。SKU、来源链接、店铺/分类编号、账号信息等不作为占位数字改写。
- 分类必须来自用户刚读取并选择的目录，填写和保存后核对完整分类路径；同名末级不能替代另一个父级下的分类。
- 可复用已有商品内容或唯一有效选项。无法核实的文字、多个可能选项、认证/资质、物流等必填资料，会显示具体未完成项目，不虚构内容或报告完成。
- 不清楚保存、认领或移动是否成功时，保留提交记录并先只读核对，不自动重复提交。

目录返回平台编号时保留该编号；页面不暴露编号时，使用实际完整路径生成带 `path:` 前缀的目录节点标识，并在操作前重新核对目录。这种标识不冒充平台分类编号。

## 与修改前的差异

| 环节 | 修改前 | 本次实现 |
| --- | --- | --- |
| 平台/店铺 | 与固定模板或做图母稿耦合 | 独立采集箱店铺绑定 |
| 领取 | 依赖另行配置店小秘分配模板 | 自动模式直接按本批绑定选择平台/店铺 |
| 分类 | 手写路径；主执行器只支持 Temu | 工作台读取真实目录；逐商品或同店批量选择 |
| 填写 | 固定包装/库存值，可能覆盖已有值 | 动态识别必填空项，保留原内容 |
| 终点 | 移入待发布后继续正式提交 | 独立待发布终点，禁止自动任务正式发布 |
| 采集回执 | 来源 URL 已选中仍强制再点击 | 唯一可见选中状态直接核实；隐藏副本不干扰 |

相关实现：`src/listing-destinations.mjs`、`src/settings.mjs`、`src/listing-workflow.mjs`、`src/dxm-required-fields.mjs`、`src/dxm-category-browser.mjs`、`src/dxm-required-platform-browser.mjs`、Temu 编辑/发布执行器及认领执行器。界面位于 `public/merchant.html`、`public/listing-workflow.html` 及对应 `public/local` 脚本。
