# 多套裂变

基于 `a6d87b3` 的场景多样性和构思可靠性更新增加，保留原来的单套生成流程。

## 使用

1. 在工作台上传并标记产品主体图，填写产品名称和真实资料，选择大师／快速模式、模型、目标市场和每套输出范围。
2. 点击「多套裂变」，选择 1–10 套及变化方式：不同人群＋不同风格、同人群不同风格、同风格不同人群。
3. 点击「推荐方案方向」。配置了构思模型时调用该模型；没有配置时明确显示本地规则推荐。逐套编辑名称、人群、关注点、场景和风格，然后确认。
4. 每套各自完成完整构思；可以查看、编辑和保存逐图方案。方向在确认后锁定，产品资料、原始参考图、输出范围和图片模型保存在本批次内。需要调整时用「复制资料，新建裂变」。
5. 确认图片数量后生成全部或指定一套。进度和结果按套显示，刷新可继续查看。单张失败可单独重生成；已有图片结果地址时可只重试下载，不重新调用生图。重生成保留上次成功图片的查看入口。
6. 下载某套或全部已完成图片。ZIP 按套分目录，包含设计方案、方向和生成状态；未完成项不会被占位图替代。

## 每套的生成标准

- 同一批次始终使用用户选定的模型和原始商品参考图；每套独立调用完整构思流程，每张独立调用图片接口，图片尺寸、质量参数和超时设置沿用单套流程。
- 方向会进入构思、分镜、单张提示词，改变人群关注点、文案语气、场景、背景配色、光影与版式；商品外形、原色和事实边界保持一致。
- 不把另一套生成的产品图作为新套图的商品来源，不因套数增加而减少每套图片、不自动降低模型。
- 白底主图和 THD 继续遵循各自约束；差异主要体现在副图和 A+。单套最多 14 张，初版仅支持大师／快速模式。
- 共用原有有界队列（默认并行 2，最多 4）。套数增加会增加总时间与真实服务用量。默认不因超时、失败或服务重启自动重新提交付费请求。
- 上述保证的是生成流程与参数一致，不能保证每张模型结果的画质都完全一致；商品还原、文字和整体效果仍需验看。

## 风格与重复文案修正

初版把创意方向追加到共用分镜后，导致不同风格仍沿用相同镜头、粗体标题和通用英文口号。新版由每套风格分别指定摄影机位、人物安排、实物比例、版式几何、光影及字体，并保留原有逐图事实边界。单套生成的既有规则不因此改写。

使用已配置的构思模型时，每段单独给出最终「画面主标题」和「画面副文案」。系统拒绝沿用旧通用标题的方案，并在生图前检查跨套主标题重复；重复项可编辑方案或只重新构思该套。用户明确指定的共同文字可以保留，产品参数不作为营销标题去重。规则构思只提供创作指引，无法提前核验模型尚未写出的成图文案。

裂变预览按原图宽高比展示，取消固定高度造成的侧边或上下填充条；下载的图片文件不被裁剪或修改。旧版已生成图片继续保留；使用新版风格需复制资料，新建批次重新构思，点击旧图重生成不会自动替换为新版方案。

## 数据和验证

批次存在 `data/workbench.json` 的 `multisets`，任务继续使用原有 `tasks`。创建、开始生成和重试有独立请求编号，用于重复请求去重。重启后已提交但结果未确认的任务显示失败，需显式处理；尚未提交的槽位可补齐。新预览构建使用单独的数据目录，不与已有服务同时写同一数据文件。

```powershell
npm.cmd run check
npm.cmd test
node tests/browser-multisets.mjs
```

自动化覆盖完整 14 张套图、固定维度、原始参考图／模型一致、请求去重、构思失败隔离、只重试下载、保留旧结果、服务重启和缺失槽位。浏览器流程覆盖方向／方案编辑、连续网络失败恢复、刷新、ZIP 内容、单图重试、复制批次和手机布局；其模拟图片只验证交互，不作为真实出图质量证据。
