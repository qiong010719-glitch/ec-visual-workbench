# 店铺裂变与单品设计统一（2026-11-15）

店铺裂变的新方案复用单品设计的完整图文分镜，风格不再删去人物或将多场景构图压缩成重复静物。生效标记为 `single-design-parity-20261115`。

## 已确认的原因

读取现有任务后确认，用户所举的宠物滑板单品任务使用 `premium_aplus_only`，包含完整环境、整体与细节关系、多场景拼图、细节与使用位置对照、选购指南。装饰画裂变使用 `main_count`；原风格覆盖器会替换原分镜的场景、动作、镜头、比例和构图，其中 `studio` 风格直接去掉完整人物。画廊风格的实存方案确实只剩静物和手部。

## 新行为

- Temu 共用流程的 `main_count` 保留原来 1—10 张槽位及首图约束。首图之后复用单品设计的完整叙事分镜，并重新组织为 1:1 方图，不另增宽幅模块。8—10 张的扩展槽位保留不同主题。
- 20 种裂变风格只附加配色、灯光、字体及照片编排节奏，保留原有场景、动作、镜头距离、人物、产品比例、证据和内容关系。简约、画廊、微距也可保留模特情境；无人物和仅手部的特写继续按原分镜执行。
- 店铺的新多产品批次固定相同目标人群，裂变不同风格。快速模式明确使用高信息密度和高场景倾向；大师模式继续使用自身摄影叙事规则。
- 单品设计与店铺裂变共用上述构思函数、参考库检索、逐图提示词及图片服务。图片模型保持用户所选型号，商品事实和参考图身份保持一致。
- 已保存方案和图片不自动改写、重生成或收费。新建批次、重新构思的新方案使用本次逻辑；已有成图的批次继续保留历史方案。
- 桌面启动检查 `temuDesignRevision`，防止新版页面复用旧生图后台。

## 验证

`tests/listing-design-parity.test.mjs` 覆盖 20 种风格、快速和大师模式、装饰画/宠物滑板/墨镜，逐项比较与单品分镜的内容一致性；检查 1、2、5、7、8、10 张的方图范围，以及显式低场景设置。

隔离接口测试从两个产品生成四套共 28 张模拟图片，同时走一键单品接口，对比实际传给图片服务的分镜、参考图、模型及比例。验证重复点击不重复提交，测试不写入真实店铺。模拟图片仅证明程序流程和提示词传递，不能作为真实模型成图质量的验收证据。

本次不提交付费图片请求。实际成图的摄影质量、人物表现、细节一致性和文字排版仍需在用户下一次新批次生成后检查。

完整测试共 280 项，首次并发执行通过 277 项，3 项遇到本机连接重置；随后按文件串行复测相关 20 项，全部通过。页面脚本与资源检查通过，隔离桌面启动检查通过。证据位于 `tests/results/listing-design-parity-tests.log`、`tests/results/listing-design-parity-recheck.log` 与 `../outputs/listing-design-parity-20261115/`。

## 使用新版

关闭现有工作台后，打开 `dist/design-parity-20261115/Temu-Workbench-1.0.3-design.1-win-x64.exe`。同一 Windows 用户下继续读取原有用户数据目录。已经出图的历史批次不会自动采用新方案；使用原素材新建批次后重新构思即可。

自动关闭旧窗口并替换原运行程序的操作被自动审批拒绝（`blocked by policy`，没有更具体原因），因此本次交付独立新版，当前运行窗口未被替换。
