# 淘宝页面收尾与无出图流程验收

2026-11-13，在 `2e18fd2` 上继续完成页面收尾。仅修改独立淘宝目录；仍使用 draft PR #7，未合并 main。

## 行为

- 图片操作统一为“修改图片”“重绘这一张”“下载原图”，成图只保留一个重绘入口。常用模式、编辑字段和生成记录使用中文。
- 淘宝面板提供“逐张要求与参考图”。卡片使用淘宝主图、SKU图、详情名称；数量仍在主面板设置。已上传SKU图时明确显示自动对应的规格图，避免手动参考选项被实际请求覆盖而造成误解。
- 修改逐张要求保留对应的已有成图，由用户主动重绘后更新；刷新保留商品资料、素材、风格、尺寸和逐张要求。
- 自定义宽高明确为构图目标，不承诺精确生成像素。成图展示实际宽高；生成档位继续为1024×1024、1536×1024或1024×1536。此轮没有新增裁切、拉伸或缩放。
- 单图和一键打包下载保留原文件字节。名称包含淘宝类别、序号、实际像素及按文件内容识别的PNG/JPEG/WebP扩展名，不再把PNG写成`.jpg`。
- 图片包只包含当前范围中已显示的主图、SKU图和详情，不混入旧范围的隐藏成图。部分图片缺失时，保留可下载图片并附“未下载图片.txt”；全部失败则不给空包。下载失败不触发重新生图。

## 验证

- 152个自动化测试通过；沿用禁止读环境文件、禁止外网和4185端口、只写本目录的测试保护，排除1项读取模拟环境文件的Apify测试。
- 22个页面脚本语法、静态资源和`git diff --check`通过。
- `tests/browser-taobao-workflow.mjs`在Edge实际操作上传、逐张要求、本地规则构思、3张模拟结果、修改要求、刷新、单图下载和ZIP下载。SKU请求只引用对应上传图，风格和专属要求送到对应任务。
- 测试中自定义主图目标为800×1200，而模拟返回为600×600。页面和下载文件均如实标明600×600，没有假称精确按目标尺寸生成。
- PNG 600×600、JPEG 640×800、WebP 750×1100分别核对文件名与SHA-256，下载字节均与模拟返回文件完全相同；故意缺失SKU图时仅打包另外两张，并列出未下载项。旧隐藏槽位不会进入当前图片包。
- 移除拖字及取消首图强制白底的浏览器回归继续通过。

本机证据：`runs/taobao-finish-20261113/tests.txt`、`tests/results/taobao-workflow/report.json`及同目录截图和下载样本。首轮浏览器脚本因评价弹窗延迟出现而超时，改为等待该弹窗并点击“跳过”后完成，无页面脚本错误。
