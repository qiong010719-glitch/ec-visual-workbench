## 接下来按顺序完成五步

1. **重新构思混合分镜。** 2026-11-21本地build时已加载原模特功能，本轮修正全人物回归。加载本轮代码后刷新4173页面，保留已选模特并重新构思；旧方案被阻断，不能靠重绘旧方案套用新规则。新页面会检查服务端模特分镜能力。
2. **真实图片小样验收。** 用客户真实商品、真实SKU和固定模特，检查主图/SKU/详情。重点看商品结构与规格、人物脸部/发型、接触关系、文字与遮挡；SKU必须仍能清楚选规格。先审小样再扩整套，不用模拟图代替质量证据。付费范围另按当次明确授权执行。
3. **接入AI视频流程。** 先确认视频渠道、模型、时长/画幅、是否配音字幕、输出数量与费用范围，再接任务提交、进度、结果保存、失败恢复和下载。延续现有人物参考，不重新随机选角；没有据此购买或提交视频服务。
4. **验收图片到视频的同一人物。** 使用客户已确认的人物成图与同一原始参考制作短样；逐镜头检查是否换脸、商品变形、人物/商品接触、服装衔接，再全片播放核对。图片通过不代表视频通过。人物与商品的审核初始状态均为待审。
5. **客户完整操作与交付。** 客户从链接/上传开始，独立完成设置、构思、出图、视频、保存、重开和下载；按客户反馈修缺陷。确认本地交付还是正式部署，再完成对应配置和说明。只有用户明确说“合”才合并，不自动上架或发布。

## 本次模特功能的具体规则

- 选“否”：不附带人物参考，提示词要求无人、无手部。不会自动改写已有图片。
- 选“是”：上传一张单人且面部清楚的参考，或选“系统生成”，填写成年模特外观/服装要求，确认费用后生成1位候选。候选完成不会替换已选人物；只有点击“使用这位模特”才固定选用。首张主图可由模特辅助展示，其余保留原分镜的无人、手部、人物安排；SKU不添加模特。只向人物/手部镜头传同一人物参考，不为身份一致而强制露脸或改变镜头。实际是否保持同一人仍需看返回结果。
- 系统模特沿用已配置的算舟图片服务，固定使用 GPT Image 2；没有新增密钥文件。模特生成独立于商品槽位，不在每张商品图前重新生成。没有可验证的实时费用报价，确认提示以供应商账单为准；不把本地模拟点数或退款当成真实账单。
- 原任务编号与候选保存在本机，生成中刷新和提交响应丢失时只查询同一任务；相同编号/要求不会重复调用。失败不自动重生，有已保存结果地址时支持仅重试下载。无结果地址时应先核对原任务及账单，再由客户决定是否重新付费生成。
- 原有按地区随机选择人种的下拉框在淘宝流程隐藏，人物以所选参考为准。模特只定义人，商品图只定义商品，对标只定义版式。
- 最多8张实际参考。需要人物的镜头中模特占1张，对标占1张；超过时提前报错，不能静默丢掉需要的人物参考。无人/SKU镜头不占模特位置。
- 模特选择、来源、原图及SHA-256进入构思、任务与草稿；系统模特另保留原生成任务编号并在服务器核对。刷新保持，恢复旧草稿默认关闭。草稿可保存“选是但尚未提供参考”的未完成设置，提交构思/生图仍会阻断。换人、开关变化或素材变化须重新构思。
- “图片／视频共用模特包”包含原图与身份记录，审核状态为 `not_reviewed`，视频状态为 `not_implemented`。文件哈希只证明用了同一文件，不证明人物视觉一致。

已移除的文字移动不再列为待修复事项；规格参数填报、单一风格强制锁定、自动上架/发布仍不在本轮范围内。对标公开使用的权利未由工程测试核实。
