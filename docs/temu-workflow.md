# Temu 图片与多套裂变工作流

Temu 使用独立入口，亚马逊首页及原有功能保留。2026-11-05 已合入上游多套裂变与生图方案升级，Temu 支持自定义 1–20 套。本说明中的尺寸、张数与图文复用是当前工作台的输出约定，不代表所有 Temu 类目的官方发布要求。

## 启动与使用

需要 Node.js 22 以上。双击根目录 `启动Temu工作台.cmd`：首次自动安装运行依赖，默认打开 `http://127.0.0.1:4183/temu`。同一服务的 `/` 仍是亚马逊入口。通过 `TEMU_WORKBENCH_PORT` 可指定其他端口，旧启动脚本和旧工作台不受影响。

手动启动：`npm ci`，随后 `npm start`；默认地址为 `http://127.0.0.1:4173/temu`。不要在旧服务占用 4173 时误以为新代码已经加载。

1. 填写商品名称和已确认的资料，上传同一商品的原图（最多 8 张）。
2. 选择 1:1 或 3:4、每套 1–7 张、语言、市场、设计模式和风格。
3. 生成设计方案，按图修改方案。修改商品资料、素材、比例或张数后须重新构思。
4. 选择生图模型，生成整套图片。首图、卖点图、细节图等组成一组，详情页直接复用。
5. 检查图片。支持下载、重新生成某张、基于成图修改以及只恢复下载；失败不会自动重复生成或切换模型。
6. 保存并导出上架资料包。草稿按平台隔离，Temu 浏览器状态不覆盖亚马逊状态。

## 多套裂变

填好上述资料并选择图片模型后，点击「多套裂变 · 最多 20 套」。选择套数和变化方式：不同人群＋不同风格、同人群不同风格，或同风格不同人群。预估数量为套数 × 每套张数，最多 140 张。

1. 推荐方向。已配置文本模型时使用模型，否则使用可编辑的资料规则；Temu 有 20 种不同摄影与排版方向，亚马逊沿用上游 10 种。
2. 逐套调整人群、关注点、场景和风格，确认后各自构思完整方案。资料、比例、模型绑定批次，修改表单不会改变已创建批次。
3. 可以编辑尚未生图的方案，再生成全部或某一套。调用图片服务前显示张数和模型确认。跨套重复主标题检查沿用上游模型方案规则；本地规则方案不冒充模型已写好的最终文案。
4. 各套独立显示任务，刷新可恢复。失败图片不会自动再次付费生成；单张重做只影响该张，保留上次成功图；仅下载失败时可以恢复已有下载。
5. 完成后导出全部上架资料包，也可单独导出已完整的一套。未完成批次不能导出成完整上架包。

上游改进会进入 Temu 的逐图镜头、展示方式、主体比例、版式和字体安排，且保留真实商品边界；首图无需强制白底，所有图按所选比例组织。单图专属要求只分配给对应图片，不广播到每张。旧方案不会自动重写，需要重新构思使用新版；实际成图仍需检查商品还原、文案与构图。

新副本不含密钥、历史商品、生成图片或历史设计参考数据。需要时在本目录 `.env` 中按 `.env.example` 配置。`SUANZHOU_IMAGE_API_KEY` 仅供图片生成，文本构思使用独立的 `PLANNER_*` 配置；缺少文本配置可使用本地规则构思。不得把专用图片密钥当成通用文本密钥。密钥文件不会纳入 Git。

## 图片尺寸

| 选择 | 请求与导出尺寸 | 使用方式 |
|---|---|---|
| 1:1 | 1024×1024 | 主图、详情页共用 |
| 3:4 | 1152×1536 | 主图、详情页共用 |

Temu 将精确目标尺寸发给图片接口，亚马逊继续使用原尺寸映射。服务商是否接受这些尺寸尚需真实账号验证；拒绝时明确失败，不会自动重发付费请求。若接口返回不同尺寸，使用 `sharp` 自动旋转并等比缩放到目标画布，必要时补白，保留完整商品和文字，不拉伸、不裁掉边缘；比例变化时界面提示检查补边。

完成记录保存目标尺寸、原始尺寸和补边标记。导出前服务端再次核对每张实际像素；错误比例不能混入 Temu 草稿。

## 上架资料包

- `images/01.png`、`02.png` 等：按首图到其他商品图排序，一张图只存一份。
- `listing-manifest.json`：平台、商品资料、比例、按相同顺序引用的 `mainImages` 与 `detailImages`；状态为未发布草稿。
- `商品草稿.json`：本地草稿记录。
- `设计方案.txt`：本套生成时使用的方案。
- `使用说明.txt`：主图/详情复用和 SKU 预览图规则。

清单中 `skuPreviewPolicy` 为 `preserve-source`，与上级上架项目的规则一致：SKU 预览图保留母稿原图，不能拿新主图替换。生成的包目前没有自动传入店小秘；价格、库存、类目和店铺匹配仍由下一部分负责，没有发布请求。

多套包使用 `schemaVersion: 2`，根目录包含 `listing-manifest.json`，每套存于 `sets/原序号-setId/`，含图片、设计方案和商品草稿。`groupId`、`setId`、`setIndex`、`draftId` 供后续流程匹配，单独导出第 2 套仍保留序号 2。`mainImages`、`detailImages` 是相对于包根目录的相同文件列表；每个文件另带 SHA-256。清单同时记录本次导出套数及原批次套数，不将子集误记为全批。

导出会核实所选各套已完成、图片存在、实际尺寸一致，全部通过后才保存草稿。导出期间图片重生成会阻止本次导出；重复导出同一套更新原草稿，不堆积副本。`POST /api/temu/multisets/:id/export` 可传 `setId` 单套导出，省略则导出全批。两平台的裂变接口和历史列表分开，Temu 为 `/api/temu/multisets`。

## 代码边界与验证

Temu 使用 `public/temu.html`、`public/local/temu.*`、`src/temu.mjs`、`src/temu-export.mjs`。两平台复用上游 `multisets` 服务与界面逻辑，Temu 通过适配器提供自己的商品资料、界面和完整上架包导出。共享构思、生图、下载恢复与草稿 API 通过 `platform: "temu"` 启用对应规则。

在本地分支 `codex/temu-image-workflow` 开发，原 Temu 入口基于 `89a8c3b`；本轮合入 `origin/main` 的 `a6d87b3` 及 `origin/codex/multi-set-generation` 的 `5ad131b`。亚马逊同步保留上游升级，本轮未推送远程、未改动原有上架脚本。

验证命令：

```powershell
npm test
npm run check
node tests/browser-temu.mjs
node tests/browser-temu-multisets.mjs
node tests/browser-multisets.mjs
node tests/browser-smoke.mjs
```

浏览器测试需要开发依赖 Playwright 和 Microsoft Edge，使用独立临时数据、明确的图片测试替身，不调用付费图片或文本模型。单套报告及截图位于 `tests/results/temu/`，Temu 多套位于 `tests/results/temu-multisets/`，亚马逊多套位于 `tests/results/multisets/`。验证覆盖 20 套 × 7 张完整方案、两种比例的实际导出像素、方向与方案修改、模型传递、刷新恢复、单图修改／重做、平台隔离、完整性校验、实际 ZIP 清单和手机布局。流程测试不代表真实生图质量或已向店铺上架。
