# Temu 图片与多套裂变工作流

当前上架目标为 Temu，做图使用原有完整通用工作台，不再采用另一套简化参数界面。首页 `/`、旧首页及 `/temu` 都显示同一工作台，商品图固定为 1:1 方图，其余选项与生图逻辑共用。没有单独的亚马逊平台入口；原有数据与规则保留，后续再接入其他上架目标。以下尺寸与图文复用是工作台约定，不代表所有 Temu 类目的官方发布要求。

## 启动与使用

需要 Node.js 22 以上。双击根目录 `启动Temu工作台.cmd`：通过上级目录 `start-listing-workbench.ps1` 启动或复用同一服务，打开 `http://127.0.0.1:4185/temu`。上架任务使用同服务 `/temu/listings`。测试统一用最新 4185 入口；旧 `TEMU_WORKBENCH_PORT` 不再使用，不要另起服务共用 `data`。自动化测试使用临时数据目录隔离真实任务。

快速或大师模式可选“仅生成 X 张主图”，再选择每套 1—10 张（默认 7 张）。单套生成与多套裂变使用同一数量，第 8—10 张仍为商品主图组，不是 A+ 模块。更改数量后重新构思；刷新会保留选择。详情页复用同组同序图片，SKU 预览图保留母稿原图。旧 7 张 + 5 张 A+ 方案仍保留，但不能直接导入当前限制为 10 张的 ERP 流程。

手动启动：`npm ci`，随后 `npm start`；默认地址为 `http://127.0.0.1:4173/temu`。不要在旧服务占用 4173 时误以为新代码已经加载。

1. 填写商品名称和已确认的资料，将同一商品的原图按主体、功能、材质细节、尺寸、互动、配件、参数说明分类上传（共最多 8 张）。
2. 沿用原有快速／大师设计、图文输出范围、模型、密度、场景、渠道、产品类型、市场、人种与文字穿插选项，新生成图片固定为 1:1、1024×1024，单张不超过 2 MB。Temu 只需主图时选「主幅图7张」或自定义主副图、不加 A+；原有 A+、THD、自定义等范围仍保留，不删通用能力。
3. 选择生图模型，点击「开始生成」，自动根据当前资料构思，再生成整套图片。构思失败就停止，不自动重试或改用旧方案。点击会使用文本与图片服务额度。
4. 如需先审阅或修改方案，使用「仅构思方案（可选）」，在「查看并修改本套设计方案」中编辑后点击「按当前方案生成」。修改商品资料、素材、比例或张数后须重新构思。首图、卖点图、细节图等组成一组，详情页直接复用。
5. 检查图片。支持下载、重新生成某张、基于成图修改以及只恢复下载；失败不会自动重复生成或切换模型。
6. 保存并导出上架资料包。草稿按平台隔离，Temu 浏览器状态不覆盖亚马逊状态。

单品一体化任务由服务端串联，资料、模型及图片张数在提交时固定；刷新页面只恢复进度，不重新构思或重复生图。服务重启后的结果不明任务不会自动重新提交。提交响应丢失时先查询原任务；尚未找到时可用原编号恢复提交。同一编号使用不同资料会被拒绝。

## 多套裂变

填好上述资料并选择图片模型后，点击「多套裂变 · 最多 20 套」。选择套数和变化方式：不同人群＋不同风格、同人群不同风格，或同风格不同人群。预估数量为套数 × 所选范围张数；7 张主副图 × 20 套为 140 张。自定义范围沿用原来的最多 14 张，不能因接 Temu 而静默减少原有范围。

1. 推荐方向。已配置文本模型时使用模型，否则使用可编辑的资料规则；Temu 有 20 种不同摄影与排版方向，亚马逊沿用上游 10 种。
2. 逐套调整人群、关注点、场景和风格，确认后各自构思完整方案。资料、比例、模型绑定批次，修改表单不会改变已创建批次。
3. 可以编辑尚未生图的方案，再生成全部或某一套。调用图片服务前显示张数和模型确认。跨套重复主标题检查沿用上游模型方案规则；本地规则方案不冒充模型已写好的最终文案。
4. 各套独立显示任务，刷新可恢复。失败图片不会自动再次付费生成；单张重做只影响该张，保留上次成功图；仅下载失败时可以恢复已有下载。
5. 完成后导出全部上架资料包，也可单独导出已完整的一套。未完成批次不能导出成完整上架包。

逐图职责、镜头、展示方式、版式、字体及参考图使用共用原生成流程，Temu 轮播首图单独采用非白底场景规则；宽幅模块也按指定画幅重新组织内容。单图专属要求仍只分配给对应图片。尺寸变更后重新构思，不能拿旧比例方案生成新比例图片；生成结果与上传 JPEG 副本都检查实际字节大小；超限时本地压缩，不额外调用生图接口。历史图片不批量覆盖。实际成图仍需检查商品还原、文案与构图。

2026-11-12 首图规则：Temu 半托管轮播首图使用突出完整商品的单一场景照片，禁止纯白抠图背景、无缝白色摄影棚背景和拼接；商品用途不明时使用有空间层次的非白色静物台面，不虚构商品事实或套装配件。依据：[店小秘半托管发布说明](https://www.dianxiaomi.com/blog/article/528)；这不代表 SKU 预览图和专用白底素材都应改成场景图。母稿 SKU 图片仍保留原图。

该规则覆盖共用流程和早期 Temu 流程的快速、大师、多套裂变，以及极速主图合图的第一个独立分镜；其他平台的白底主图、THD 和仅 A+ 范围保持各自规则。构思系统指令、首图段落和生图最终约束使用同一规则。旧方案未标记当前首图规则版本时，提交首图会在调用图片服务前提示重新构思；已生成过图片的裂变批次需复制资料新建，原方案、图片和下载恢复均保留。

新副本不含密钥、历史商品、生成图片或历史设计参考数据。需要时在本目录 `.env` 中按 `.env.example` 配置。`SUANZHOU_IMAGE_API_KEY` 仅供图片生成，文本构思使用独立的 `PLANNER_*` 配置；缺少文本配置可使用本地规则构思。不得把专用图片密钥当成通用文本密钥。密钥文件不会纳入 Git。

## 图片尺寸

| 选择 | 请求与导出尺寸 | 使用方式 |
|---|---|---|
| 1:1 | 1024×1024 | 主图、详情页共用 |
| 历史 3:4 | 1152×1536 | 仅保留旧任务读取与下载恢复，新生成任务使用 1:1 |

当前工作台将精确目标尺寸发给图片接口。服务商是否接受这些尺寸尚需真实账号验证；拒绝时明确失败，不会自动重发付费请求。若接口返回不同尺寸，使用 `sharp` 自动旋转并等比缩放到目标画布，必要时补白，保留完整商品和文字，不拉伸、不裁掉边缘。独立编辑工具及原手机重排工具仍保留各自的图片处理用途。

完成记录保存目标尺寸、原始尺寸和补边标记。导出前服务端再次核对每张实际像素；错误比例不能混入 Temu 草稿。

## 上架资料包

- `images/01.png`、`02.png` 等：按首图到其他商品图排序，一张图只存一份。
- `listing-manifest.json`：平台、商品资料、比例、按相同顺序引用的 `mainImages` 与 `detailImages`；状态为未发布草稿。
- `商品草稿.json`：本地草稿记录。
- `设计方案.txt`：本套生成时使用的方案。
- `使用说明.txt`：主图/详情复用和 SKU 预览图规则。

清单中 `skuPreviewPolicy` 为 `preserve-source`：SKU 预览图保留母稿原图，主图和详情图保持原顺序与内容。「Temu 上架任务」进入店小秘执行页面，可选择工作台生成的批次或草稿导入。做图与导出本身不会写入店铺；保存到待发布的真实执行结果以该上架任务的回读核验记录为准。

多套包使用 `schemaVersion: 2`，根目录包含 `listing-manifest.json`，每套存于 `sets/原序号-setId/`，含图片、设计方案和商品草稿。`groupId`、`setId`、`setIndex`、`draftId` 供后续流程匹配，单独导出第 2 套仍保留序号 2。`mainImages`、`detailImages` 是相对于包根目录的相同文件列表；每个文件另带 SHA-256。清单同时记录本次导出套数及原批次套数，不将子集误记为全批。

导出会核实所选各套已完成、图片存在、实际尺寸一致，全部通过后才保存草稿。导出期间图片重生成会阻止本次导出；重复导出同一套更新原草稿，不堆积副本。`POST /api/temu/multisets/:id/export` 可传 `setId` 单套导出，省略则导出全批。两平台的裂变接口和历史列表分开，Temu 为 `/api/temu/multisets`。

## 代码边界与验证

页面直接复用 `public/index.html` 与原有脚本，通过 `shared-temu-bootstrap.js` 隔离浏览器存档，通过 `shared-temu.js` 增加尺寸及 Temu 草稿／上架入口。请求携带 `image_workflow: "shared"` 和 `image_ratio`，进入同一个 `planner` 和 `multisets` 服务。`platform: "temu"` 负责批次／草稿归属、精确尺寸处理和首图约束，设计风格仍共用。早期简化 Temu 页面与请求仅保留兼容代码，正常页面不使用；旧资料与完成图可迁移，旧方案须重新构思。`legacyUi:true` 只在独立回归测试中关闭目标适配器，验证原功能没有被改坏。

在本地分支 `codex/temu-image-workflow` 开发，原 Temu 入口基于 `89a8c3b`；本轮合入 `origin/main` 的 `a6d87b3` 及 `origin/codex/multi-set-generation` 的 `5ad131b`。亚马逊同步保留上游升级，本轮未推送远程、未改动原有上架脚本。

验证命令：

```powershell
npm test
npm run check
node tests/browser-temu.mjs
node tests/browser-temu-multisets.mjs
node tests/browser-multisets.mjs
node tests/browser-smoke.mjs
```

浏览器测试需要开发依赖 Playwright 和 Microsoft Edge，使用独立临时数据、明确的图片测试替身，不调用付费图片或文本模型。单套报告及截图位于 `tests/results/temu/`，Temu 多套位于 `tests/results/temu-multisets/`，亚马逊多套位于 `tests/results/multisets/`。验证覆盖 20 套 × 7 张完整方案、两种比例的实际导出像素、方向与方案修改、模型传递、刷新恢复、单图修改／重做、平台隔离、完整性校验、实际 ZIP 清单和手机布局。流程测试不代表真实生图质量或已向店铺上架。
