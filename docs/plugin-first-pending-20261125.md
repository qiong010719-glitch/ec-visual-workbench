# Temu 前端采集、批量认领与待发布

更新：2026-11-25。维护位置仍为新版跨境工作台，端口 4196。

## 用户已确认的完整流程

1. 输入关键词，在 Temu 主搜索结果逐件打开商品详情，点击店小秘“开始采集”。
2. 前端显示重复时跳过该商品，继续下一件；不在采集前进入采集箱按来源 URL 查重，不确认重复采集。后续数量规则以 [重复跳过并补足新增数量](duplicate-target-count-20261125.md) 为准：重复不占目标，补充候选直到新增成功数达标。
3. 本批采集结束后，在通用采集箱定位本批新采集记录，批量认领到后台绑定的目标平台、店铺和站点。
4. 在工作台读取真实分类目录，由用户选择正确末级分类；程序将分类填入对应平台商品，并批量补齐必填空项。
5. 保存并核对后，统一转入待发布，流程到此结束。

后两阶段已在此前“核对希音分类与上架流程”对话中明确，并在 2026-11-24 接入。当前默认流程使用独立采集箱店铺绑定，不以旧固定模板为前置条件。历史固定模板入口保留，但不是默认路径。

## 本次修改

- 移除新商品的采集箱查重和整批预检查屏障。已完成的历史批次不再提前替前端决定重复；已有提交结果不明确的任务仍保留原意图并核对，普通继续不重放点击。
- 识别插件面板、明确的网页重复弹窗以及浏览器原生重复确认框。记录 `skipped-duplicate`，返回本任务搜索页，继续下一件。原生确认框只允许取消已识别的重复提示；已有 Chrome 连接仍校验任务标签所有权。
- 重复跳过与成功入箱分别统计。全批均为重复时采集处理可以完成，但成功入箱为零；重复项不自动带入本批认领。
- 采集结束后的记录定位用于精确认领，不是新商品点击前的查重。插件成功提示与真实通用采集记录分别留存。
- 采集页显示“前端采集 → 批量认领 → 补全至待发布”，本批入口带上 `freeJobId`，跳转到现有默认补全流程。
- 脚本运行副本与打包副本同步修改；工作台及启动器版本同步为 `crossborder-plugin-first-20261125-1`，采集版本为 `plugin-first-duplicate-skip-20261125-v22`。

## 后两阶段的实际代码

`src/listing-workflow.mjs` 建立批次与店铺范围，执行认领、分类选择、补全和转待发布；`src/dxm-allocation-browser.mjs` 精确选择本批通用记录并认领到指定店铺；`src/dxm-required-platform-browser.mjs` 与 Temu 执行器承担分类、必填补全、保存和待发布回读。

默认流程支持 Temu、SHEIN、TikTok 目的地。同平台、同站点的多家店可一起建任务，不同平台/站点分组处理。目标店铺和正确分类需要在工作台选择；没有把缺失的分类猜成其他商品类别。数值空项按既有字段规则补齐，已有内容保留，不能确定的必填选项会列出具体缺项。自动补全任务的后端禁止正式发布。
