# 同机全新用户验收

目的：保留原工作台，使用另一个独立文件夹验证首次使用和后续重启。它是同机应用数据隔离，不代替 Windows 沙盒、虚拟机或第二台电脑的系统依赖验收。

## 启动与数据边界

桌面入口支持 `WORKBENCH_DESKTOP_DATA` 指定独立用户目录。这同时改变 Electron 的用户目录和服务端业务数据目录；专用 Chrome 数据保存在该目录内的 `preferences/chrome-profiles`。

指定独立目录时：

- 不导入旧店铺，不继承宿主环境变量中的模型密钥。
- 自己启动本地服务，绝不连接原工作台已经运行的服务。
- `WORKBENCH_DESKTOP_PORT` 可指定固定端口，默认 4191；端口冲突会报错停止。
- 固定端口保证关闭重开后页面偏好仍属于同一来源。
- 窗口标题为“全新用户测试 · Temu 工作台”，单实例锁按独立用户目录区分。

普通入口保持原来的数据目录与 4185 端口。自动化验收仍可用 `WORKBENCH_DESKTOP_TEST=true` 分配临时端口。

## 创建测试文件夹

先打包并审计桌面程序，再运行 `tools/prepare-fresh-user.mjs <win-unpacked目录> <新目录>`。工具拒绝覆盖已有目录，只复制程序，并创建空的用户数据目录、素材目录和中文说明。

使用生成的“双击启动全新用户测试.vbs”打开。启动器使用系统运行环境，不继承开发机的 API 密钥或开发工具 PATH。必须通过这个入口启动隔离档案；直接打开底层 EXE 不会带上隔离参数。

关闭并重开会保留本轮测试配置。再次从零测试应创建另一个空目录与空闲端口，不删除原工作台或当前已配置的测试档案。

## 验收顺序

1. 首次打开：店铺、母稿、浏览器、ERP、密钥和任务为空。
2. 手工配置新的 Chrome 专用窗口，独立登录 ERP，不复用旧比特窗口或浏览器同步。
3. 手工新增店铺和母稿，验证上架页同步和切换。
4. 配置模型后，由用户明确开始一件商品的小批量生成与“仅保存草稿”验收。
5. 关闭重开，检查配置与进度恢复，再安排发布和异常恢复测试。
6. 通过后，在干净 Windows 环境验证安装、依赖、权限与首次运行。

同一个 ERP 账号登录后仍会显示其云端店铺。需要验证空白云端账号时，须使用专门的测试账号或测试店铺。

自动化证据：`tests/desktop-profile.test.mjs` 检查启动配置；`tests/desktop-profile-isolation.mjs` 检查双实例、缓存/登录隔离及重启；`tests/desktop-fresh-install.mjs` 检查打包运行、导入、配置加密与持久化。测试使用临时档案，不写真实商家数据，也不执行收费生成或商品发布。
