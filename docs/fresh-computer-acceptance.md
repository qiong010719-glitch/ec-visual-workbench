# 新电脑基础验收：第一步

本轮先确认：另一台 Windows 电脑拿到软件后，可以独立打开、导入素材、保存配置并重新打开。会员码、云端额度、付费生成和真实商品发布不在本轮验收范围内。

后续版本说明：2026-11-11 的 `1.0.1-test.2` 已补充海报母稿 SKU 图片前置校验，见[本地业务稳定性验收](local-business-acceptance.md)。下文保留最初 `test.1` 包的验收记录；新电脑启动及导入步骤仍适用于新包，不能把旧包测试结果当成新包结果。

## 交付物

- 内部测试版：`Temu-Workbench-1.0.1-test.1-win-x64.exe`。
- 这是 Windows x64 单文件便携版，双击启动，首次启动需要解压运行文件。不是正式安装程序，尚未做发布者签名。
- 程序自带运行环境，不要求安装 Codex、Node.js、Python 或复制开发项目。
- 店小秘自动操作另需配置 Chrome 专用窗口或比特浏览器；基础启动测试可以先不配置它们。
- 测试文件夹内附本地测试素材；这些是纯色测试图片，不执行 AI 生图，不产生模型费用。

## 在另一台电脑按顺序操作

只复制交付文件夹。在有写入权限的文件夹内运行，比如桌面下新建“工作台测试”；不要复制原电脑的配置或密钥文件。

| 步骤 | 操作 | 通过标准 |
| --- | --- | --- |
| 1 | 记录 Windows 版本、系统架构，然后双击测试版 exe | 出现工作台窗口，且不需要开发工具或管理员命令 |
| 2 | 打开“连接设置” | 首次运行没有开发者的店铺、浏览器或模型密钥；如果之前装过本软件，记录为已有用户环境，不算首次空配置测试 |
| 3 | 依次打开“单品设计 / 店铺上架 / 连接设置” | 三个页面能显示，无空白、卡死或持续报错 |
| 4 | 在“店铺上架”点击“浏览”，选择附带的“验收素材”文件夹，再点“读取素材” | 原生文件夹窗口可操作；读到 FRESH-001、一张纯色图片，名称为“新电脑导入测试” |
| 5 | 在连接设置的文本模型密钥栏填 `fresh-computer-test-only` 并保存；此值只是测试占位，不调用模型 | 显示已配置，输入框清空；不要点击生成、测试模型或上架按钮 |
| 6 | 正常关闭软件，再双击同一 exe，回到连接设置 | 能再次启动，仍显示文本密钥已配置 |
| 7 | 记录每步通过/失败，附出错页面或系统提示截图 | 能根据具体步骤复现；不要拍摄或发送真实密钥 |

任一步失败就先停在该步，把提示反馈回来。全部通过后，下一步再测试新电脑上的浏览器、店小秘登录、两家店铺与母稿读取，以及保存后同步到上架页面。

## 本机证据与边界

自动化脚本 `tests/desktop-fresh-install.mjs` 分别测试打包后的程序目录和最终单文件便携版，使用独立数据目录、中文及空格工作路径、仅含 Windows 系统目录的 PATH。测试数据与真实商家数据隔离。

测试覆盖图片/Excel 导入、配置加密保存、关闭重开恢复、三个页面、当前新增店铺入口与母稿选择控件，以及随包 ERP 模块能否加载。ERP 检查连接的是本地模拟的关闭窗口，不操作真实账号。

程序目录测试中的文件夹选择窗口返回值由测试替代；便携版通过输入路径导入。所以真实原生文件夹选择仍必须完成上表第 4 步。

这些结果不能替代新电脑实测，也不能证明 Windows 各版本、标准用户权限、杀毒软件兼容、真实店小秘上架、视频生成或会员额度计费已经通过验收。测试通过前不对外销售。

## 复现本机测试（开发人员）

在应用仓库中运行：

```powershell
npm run check
node tests/desktop-fresh-install.mjs
node tests/desktop-fresh-install.mjs --portable --executable dist/new-computer-20261111/Temu-Workbench-1.0.1-test.1-win-x64.exe
node tests/desktop-package-audit.mjs
```

报告位于 `tests/results/fresh-install/`。交付清单记录实际 exe 的 SHA-256；换包必须重新测试和生成清单，不能复用旧报告。
