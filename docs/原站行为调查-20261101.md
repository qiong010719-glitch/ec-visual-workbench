通过已连接的 Chrome / browser-skill 新建任务窗口，在打开网站前启动网络记录。依次打开首页、点击游客预览、打开模式详情，读取页面及展示案例。没有提交登录、注册、联系站长、素材上传、构思或生图请求，没有修改请求、重放请求或改变权限标记。任务结束已停止采集并关闭自己的浏览器会话。

证据目录：`reference/behavior-20261101/`。包括首页、游客和模式详情文本、模式截图、交互间隔、网络元数据及文件哈希。导出后仅保留请求元数据，移除正文、请求头、响应头、查询参数及页面内部数据。完整网络导出已从项目目录移除。

## 已能还原的接口形状

| 阶段 | 公开前端契约 | 尚缺的核心 |
| --- | --- | --- |
| 资料与素材 | 产品名称/描述/强制要求、市场语言、人物、分类素材、图片配额 | 图片理解结果及事实提取规则 |
| 构思 | `POST /api/agent`，由 `agent_tasks/<本次ID>` 监听 `status` / `result` | 专家提示词、策划模型、逐图方案结构与运行记录 |
| 生图 | `POST /api/generate`，发送 `sop_text`、`firebase_tasks`、`slot_directives` 等 | 每张最终 prompt、参考图选择、模型实参及供应商结果 |
| 极速 | `POST /api/ultra_generate`，跳过前端构思步骤，合图后裁切 | 服务端合图策略及稳定性 |
| 局部编辑 | `POST /api/inpaint`，底图、标注/文字、素材与比例 | 编辑模型实际能力、遮罩处理及一致性策略 |

上述路径来自公开代码。没有使用它们读取未知任务、访问他人数据或尝试绕过登录。

## 公开样片能够说明什么

已查看公开保存的 `public/mode-samples/master_case1_a.jpg` 与 `fast_case1_a.jpg`。大师样片的不同画面承担产品全貌、材质/成分、使用场景等不同内容，快速样片也采用不同卖点及布局。它们可作为整套图分工和构图变化的视觉参考。

这两套样片是不同商品，未取得其完整输入、参考素材、提示词、筛选过程或生成次数，不能据此做严格的模式因果比较，不能复用其中的商品功效、尺寸或认证作为本项目商品事实。

## 与当前本地实现的差距

本地 `src/planner.mjs` 默认使用规则方案；所有非主图目前只有同一句笼统设计要求。`src/server.mjs` 普通批量路径对每张传入同一份 SOP，主要以末尾槽位名称区分。此前真实任务中卖点图 1 与卖点图 3 的提示词仅编号不同，已核实。

本地接口和界面测试通过不能证明设计能力等价。此前交付的是前端复刻及自行重建的后端，不是已取得原站核心的实现。

## 后续可执行路线

在缺少登录和原站输入输出样本的条件下，继续增加抓取次数不能验证隐藏生成链路。可在现有公开契约基础上自主重建以下能力，并明确标记为重建：

1. 解析已提供产品事实，分别记录确证资料、未确认信息及素材用途。
2. 为整套图片分配独立卖点、镜头、场景、构图、文案与参考图；保留公共色彩和字体规范。
3. 将整套策划转为逐张独立提示词，校验槽位覆盖、重复内容及强制要求，不再仅替换编号。
4. 让快速/大师模式真正改变信息密度与视觉规划，以用户的实际商品进行本地质量验证。
5. 若以后获得原站可用账号或同一商品的成对输入/输出，再补做对照实验；在此之前不报告一比一效果或原版私有提示词已还原。

本轮没有修改本地生成实现、重启工作台、调用付费模型或更改现有图片。
