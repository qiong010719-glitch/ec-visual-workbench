# 固定上架模板：长期保存与逐店执行

更新：2026-11-23。入口为工作台 `/sourcing/listing`，也可从免费选品页的“固定上架模板与执行”或某批次的“继续本批认领核对与上架”进入。

固定模板现已支持统一分类、包装尺寸和重量、每个SKU库存，以及“先保存草稿、之后修正包装”的操作。新功能已完成隔离测试；当前30件×2店已实际核对60条采集箱草稿，但本批尚未执行商品保存或发布，不能据此宣称全流程已实测通过。

## 先分清三个阶段

| 阶段 | 在哪里操作 | 完成后得到什么 |
| --- | --- | --- |
| 选品采集 | 工作台输入关键词、数量；当前来源固定为Temu前台，通过店小秘插件采集 | 店小秘“产品 → 通用服务 → 数据采集”中的来源记录 |
| 认领分配 | 对本批记录使用店小秘人工维护的认领分配模板，例如“画板” | 指定目标平台、店铺、站点的采集箱记录 |
| 补全与上架 | 在工作台选择固定上架模板和本次处理店铺，核对后填写、保存，再提交发布 | 每家店分别记录保存、发布提交、审核及平台在售结果 |

选品采集不要求选择上架店铺。连接哪个店小秘账号属于账号设置。采集记录已核实，不代表已认领到目标店铺；认领到采集箱也不代表已经上架。

**认领分配模板**保存在店小秘，决定商品送到哪些采集箱。**固定上架模板**保存在工作台，保存入箱后的商品填写规则和各店配置。两者分别选择、分别记录。店小秘的产品模板、变种模板、运费模板也有各自用途，不能混用；本流程不以商品母稿为前置条件。

当前固定模板执行适配 **Temu半托管**。界面允许保存TikTok配置，TikTok的固定模板核对、自动填写和发布执行尚未接入；多平台是后续扩展范围。既有其他流程的能力不自动等同于这条新联动流程的能力。

## 首次保存固定上架模板

1. 点击“新建模板”，填写名称、店小秘账号、目标平台、业务类型、销售站点和适用商品类型。建议按商品实际填写方式命名，例如“Temu半托管·加拿大·带框帆布画”。
2. 填写已确认的完整分类路径和共用属性，选择分类应用方式。同一批确实属于同一商品类型时，可以统一使用模板分类；混有不同类型的商品应先分组，不能只按搜索关键词判断。
3. 在“统一包装与库存”中填写需要共用的包装长、宽、高和重量，设置每个SKU库存，并选择保存方式。数值尚未确定时可先保留原值，不会自动猜测包装数据。
4. 添加适用店铺，逐店填写准确店铺名称、站点、仓库、运费模板和发货时效。当前一个模板使用同一销售站点，各店绑定站点应与模板一致。仓库或运费不同可保存在各店配置中，无需复制整套商品规则。
5. 点击“保存固定模板”。暂不完整也可保存模板，页面会列出待补项；保存模板本身不会修改店小秘商品。正常复用时直接选择已保存模板，无需每批重填。

| 模板设置 | 应用方式 |
| --- | --- |
| 本批商品统一使用模板分类 | 填写完整路径，并替换本批商品已有的不同分类；仍核对商品和SKU身份、原规格及价格是否保留 |
| 仅补空分类，已有分类须与模板一致 | 补充空分类，遇到已有不同分类时停止该条；旧模板默认沿用此方式 |
| 包装长、宽、高和重量 | 尺寸统一使用cm，重量使用kg；四项须一起填写大于0的数值，应用到每个SKU。全部留空或点击“保留原包装参数”则保留商品原值 |
| 库存 | 新模板默认每个SKU统一10000，可改为其他非负整数或“保留每个SKU原库存”；旧模板未配置库存规则时保留原值 |
| 包装待补时先保存草稿 | 新模板默认使用。分类、属性、标题、价格、库存和物流等资料先补齐；仅包装尺寸或重量待补时可以尝试保存草稿，回读并继续显示包装缺项，此时不能发布 |
| 资料完整后保存 | 旧模板默认沿用此方式。商品上架资料检查全部通过后才保存 |

标题、价格、图片及原商品规格继续保留。仅按明确保存的规则修改分类、共用属性、物流、包装和库存；其他已保存规则会保留，执行器未支持的规则会明确提示。包装默认值适合先批量填写，再逐SKU修正差异；正式发布前应使用实际包装数据，商品尺寸不能直接当作包装尺寸。

模板可“编辑”或“复制另存”。修改已有模板产生新版本，例如v1 → v2；复制产生独立模板，从v1开始。模板与任务都保存到工作台数据目录，刷新页面或重启后可读回。

建立任务时会冻结选中的模板版本、商品范围、店铺范围和账号/浏览器绑定。修改模板用于后续新任务，已有任务继续使用创建时的快照。临时取消本次不处理的店铺不会改变长期模板绑定。账号绑定变化、版本冲突或文件损坏会阻断继续执行，不会悄悄替换原配置。

## 每批怎样操作

1. 在“本次处理范围”选已采集批次，仅勾选已经核实的通用采集记录。选择固定上架模板及本次要处理的店铺；模板与采集批次必须属于同一店小秘账号。
2. 点击“建立本批上架任务”。这一步只保存任务范围，不会直接认领、改商品或发布。任务结果按“来源商品 × 目标店铺/站点”展开。
3. 点击“核对认领与资料”。程序查找各店对应的实际采集箱记录，核对来源商品、店铺、站点和草稿身份。找到唯一记录就复用；尚未认领会单独提示。
4. 如出现多条候选记录，在该商品行选择本次实际要用的草稿，点击“使用这条记录”，然后再次核对。候选选择只固定记录身份，执行前仍会重新检查，不会按列表第一条猜选。
5. 需要认领时，展开任务内“认领分配模板”，输入店小秘中已人工维护的模板名称并点击“读取店小秘认领模板”。不填名称时可能只读到目录；选择模板前需按名称读取完整目的地。核对后点击“绑定本次认领模板”。
6. 当任务允许时，点击“按分配模板认领缺失商品”。程序只勾本批对应的通用记录，重选同一模板，比较实际完整目的地，勾选“已认领至相同店铺的产品不再认领”，保存提交意图后确认一次。已有目标记录复用，提交后仍要回查各店采集箱。
7. 模板配置和商品定位允许时，点击“按模板填写并保存”。程序逐店、逐商品应用分类、共用属性、物流、包装与库存规则，按模板的保存方式处理，保存后独立回读。选择“包装待补时先保存草稿”时，已保存商品仍可能列出包装缺项；其他上架资料须先补齐。界面一次建立任务，不代表店小秘能跨店一次保存。
8. 如需调整包装，打开对应店小秘草稿，修改各SKU的包装长、宽、高或重量并保存，再回工作台点击“核对包装修改”。这个动作只回读并接收包装参数差异，不重新保存商品。它仅适用于已确认保存、没有未决提交且尚未移入待发布或提交发布的任务；其他商品信息变化会继续提示核对，不会一并接受。
9. 商品资料全部完整且服务端允许时，才会出现“提交发布”。保存和发布是两个动作。点击发布后仍要核对实际状态，未确认平台在售的条目继续保留待核对状态。

若“画板”实际绑定Temu半托管的店铺1、店铺2测试及加拿大站，本次选择30件商品和这两家店，会建立 **30件来源商品、2家店、60条目标处理记录**。其中可以有已认领记录；60条目标记录不等于新认领60条，也不等于60条保存成功或平台在售。每一条都要有相应证据。

当前认领联动要求：**认领分配模板的完整平台、店铺、站点集合，必须与本次任务选中的上架目的地完全一致**。例如任务只选店铺1，而“画板”同时绑定两店，就不能用该模板提交；应调整本次任务范围，或在店小秘人工维护匹配的分配模板并重新读取。程序不会悄悄删掉模板中的其他目标或扩大本次范围。模板名称、编号或实际勾选发生变化，也需重新同步后处理。

## 资料缺失时会停在哪里

模板“配置已保存”只说明配置已落盘；“配置完整”也不证明商品已符合上架要求。执行时还会检查实际页面：

- 正确账号、来源商品、目标店铺、站点和唯一草稿；通用采集记录和平台采集箱记录分别核对。
- 完整商品分类、分类展开后的必填属性、页面校验错误、产地等真实必填内容。
- 正确且唯一的仓库、该店可用的运费模板和明确的发货时效。
- SKU身份、价格、尺寸、重量、库存及商品媒体等资料是否完整、是否意外变化。

例如缺少省份、分类属性、有效标题、价格、库存或物流设置时，两种保存方式都会列出具体缺项并停止保存、发布；不会用猜测值凑齐。仅包装尺寸或重量待补时，“资料完整后保存”停止保存，“包装待补时先保存草稿”允许在其余检查通过后尝试保存。必须取得实际保存回执及回读结果才能记为已保存；店小秘若拒绝保存，也会保留实际错误。

已有分类与模板不同，按所选的分类应用方式处理；配置选项不存在、SKU未加载、包装单位无法确认、已有其他仓库可能影响库存，或修改导致原图片、规格、价格等意外变化时，都会停止该条。允许保存包装待补草稿不等于放过这些定位和修改检查。

补齐适用的真实资料后，应先核对当前任务状态再继续。更新固定模板不会改写旧任务快照；若需要使用新版本，先处理原任务的待核对提交，再明确建立使用新版本的任务。不要为避开待核对状态而重复创建、认领或发布同一商品。

## 超时、暂停和重启

认领、商品保存、移入待发布、发布各自记录提交意图。点击后超时、连接中断或没有可靠回执时，结果是“待核对”，不能推断失败，也不会自动再点一次。

此时使用“只核对结果”，回查原账号、原商品和原记录。刷新工作台页面只读取状态，不重新提交；建立任务请求丢失响应时，工作台用原请求ID查询，支持恢复已去重的任务。服务重启或中断后也先核对已有提交。点击“暂停后续条目”保留已完成记录和现场，不撤销已经发出的请求。

若核对仍不能确认结果，保留任务和错误信息，先查清原提交。模板保存、认领成功提示、按钮已点击、当前列表总数都不能替代逐项结果证据。

## 怎样判断结果

| 页面状态 | 可以确认的事实 | 还不能据此确认的事实 |
| --- | --- | --- |
| 已确认通用采集记录 | 来源商品在通用数据采集中已核实 | 已进入某店采集箱 |
| 已定位店铺商品 / 已确认认领 | 对应目标店铺、站点已有确定记录 | 商品资料完整、已发布 |
| 草稿已保存并回读，仍有待补项 | 保存回执和独立回读已确认，包装缺项仍保留 | 可以提交发布 |
| 已保存并核对 | 本次填写已保存且回读一致 | 已提交发布或平台在售 |
| 已提交发布 | 发布请求已接受或仍在提交 | 平台审核通过、上架完成 |
| 店小秘在线，平台状态待同步 | 店小秘在线列表已有记录 | 平台已经在售 |
| 平台审核中 / 平台待上架 | 已读到该平台阶段状态 | 平台已经在售 |
| 平台在售 | 已取得与本条商品对应的平台在售状态证据 | 其他商品也成功 |
| 结果待核对 / 失败 | 该条需要核对或已有失败原因 | 可直接重试原提交 |

发布完成按每条记录的真实状态统计。店小秘“在线”列表、发布成功提示和平台实际“在售”分开记录；部分成功不会把整批记成全部完成。
