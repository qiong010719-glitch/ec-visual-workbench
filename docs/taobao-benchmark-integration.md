# 淘宝对标链接接入与验收

日期：2026-11-14。基于 PR #7 的 `ec70a0972f479e2143f501ce973c6bad2d5779f1`，新分支 `codex/taobao-benchmark-links`；保持 draft，不合并 main。

## 页面操作

工作台的淘宝张数、尺寸设置下方新增「对标链接与版式参考」折叠区。

1. 填写本品名称、真实卖点，上传自己的主体图和对应 SKU 图；设置本次主图、SKU、详情张数与画幅。
2. 粘贴一个淘宝／天猫完整商品链接，或含 `e.tb.cn`、`m.tb.cn` 链接的分享文案。点击「读取链接图片」后才会请求抓取服务。
3. 查看按来源分组的主图、SKU、详情原图，为需要参考的输出逐张选择同类图片。默认不自动绑定；缺失的详情不会用主图补成详情。
4. 点击「分析并用于构思」。只分析选中的不同参考图，发送真实图片字节，提取背景、配色、文字层级、主体位置与阅读顺序；分析不启动生图。
5. 继续本站的「一键构思」，审看并修改逐图方案，再点击原有生成按钮。成图旁显示这张实际使用的版式参考，可打开查看；单图和 ZIP 仍下载原文件。

每张绑定图送入图片模型时，前面是本品身份图，最后一张是这张输出的对标图。SKU 继续使用既有逐槽 SKU 参考逻辑。本品身份图最多 7 张，为对应对标保留 1 张；没有本品图时在提交生成前报错。

没有绑定的图片沿用现有构思。改变绑定后需要重新构思；修改逐张要求、关闭或清除对标会保留本品素材和已有成图。改变输出张数导致槽位分类变化时，旧分类绑定不迁移到新分类。

## 接入边界

- 第一版支持淘宝／天猫，不宣称源项目支持的其他平台都已接入本网站。
- 主图、SKU、详情仍使用本站的数量、画幅、整套风格、逐张要求和图片模型。第一张主图没有重新加上白底要求；文字拖动没有恢复。
- 对标图用于布局和表达，本品图和已知事实决定商品、颜色、结构、SKU及文案。提示词明确排除竞品品牌、价格、参数、销量、认证和营销承诺；这不是模型永不出错的保证。
- 不新增发布、自动上架、视频、规格填报、自动多轮修图功能。没有修改 Temu 或裂变项目，也不调用源项目的服务。
- 本轮用户授权了接入开发；旧门禁中的法务同意没有记录。当前仅交付 draft 代码和模拟验收，真实复刻试跑与对外使用前仍需按原门禁确认。没有将本轮接入请求解释为付费试跑或合并授权。

## 服务、数据与重复请求

- 抓取使用现有万邦 `taobao/item_get_pro`，一次任务单次请求。凭据只在服务进程内读取已有 `%LOCALAPPDATA%\LinkToListing\onebound.json`，或显式传入的 `ONEBOUND_API_KEY` / `ONEBOUND_API_SECRET`；不复制密钥到项目配置、网页、提示词或任务记录。
- 视觉分析沿用本站 `VISION_*`，缺省回退到 `PLANNER_*`；状态显示「已配置」只表示配置存在，不证明在线接口可用或模型支持图片。图片生成提供商与型号未改变。
- 新接口为 `/api/taobao/benchmarks` 与 `/api/taobao/benchmark-analyses` 的提交、状态查询；沿用本机会话保护。读取状态只发 GET，不重新提交。
- 每次点击先保存请求编号，再提交。重复编号返回同一任务；相同链接正在读取、同一资料正在分析时拒绝重复提交。超时、响应未知、重启后都不自动重发模型或抓取请求。
- 图片保存在 `data/media/`，资料和版式结果保存在 `data/taobao-benchmarks/benchmarks.json`，包含来源链接、分组、顺序、本地地址、SHA-256、时间、任务状态。
- 已成功的同商品资料可以复用；使用缓存前检查原图文件与哈希。文件丢失或变化时，用户主动再次读取会重新抓取。部分图片或分析失败时保留已成功结果；下一次明确的分析操作只处理尚未分析的选择。
- 不向本品素材库加入对标图片。服务器忽略客户端自填的版式和内部路径，只接受已保存、已分析的绑定编号；生成前再次核对文件哈希，并保存实际参考图顺序与角色。

## 本轮验收

所有写入、服务临时目录和测试结果都在淘宝独立目录。自动测试启用已有只写本目录、拒绝 `.env` 读取、拒绝外网及 4185 的防护。

| 检查 | 结果 |
|---|---|
| 页面脚本与静态引用 | 23 个脚本语法通过，静态引用齐全 |
| Node 自动测试 | 164 项通过；为了遵守不读取 `.env`，命令排除了既有的那一项 Apify 凭据文件测试，未将它计为本轮通过 |
| 新增对标后端测试 | 10 项：链接与长编号、跳转限制、分类、凭据脱敏、真实字节分析契约、缓存与防重、三类逐张绑定、坏缓存恢复、生成前拒绝无效输入、部分失败与重启 |
| `browser-taobao-benchmarks.mjs` | 8 组检查通过；真实网页操作、模拟抓取/分析/3张生成；三种输出各带对应参考，SKU保留自己的身份图，刷新恢复、清除、单图和ZIP字节核对正常 |
| `browser-taobao-workflow.mjs` | 原有不选对标的 5 组流程检查通过，3 张模拟生成 |
| 外网与付费操作 | 上述浏览器测试外网请求为 0；本轮真实抓取、视觉分析、生图均为 0 |

本机 4173 已加载新接口：抓取配置与视觉分析配置均返回已配置，图片服务仍为 `gpt-image-2`，查询时运行中和排队任务均为 0。该检查只读取本机状态，没有验证外部服务或消耗额度。

本机证据：`runs/taobao-benchmark-20261114/tests.log`、`browser.log`、`browser-default.log`，以及 `tests/results/taobao-benchmarks/report.json`、`tests/results/taobao-workflow/report.json`。截图中的几何图案明确标为本地测试素材，不能当真实复刻质量证明。证据目录不提交到 PR。

复现：使用 Node 22+，按项目既有命令检查；浏览器测试需要 Playwright 和 Edge。测试可通过 `PLAYWRIGHT_MODULE_URL` 指向本机已安装的 Playwright，临时目录放在本仓库的 `tests/results/` 下。

## 尚未验收

真实商品的万邦返回结构和图片可达性、当前视觉模型的实际识别效果，以及最终图片保留本品身份并贴合参考版式的质量，都尚未通过本轮实图验证。后续应先用一条已获准使用的链接验证抓取，再选少量参考分析，最后按明确额度许可各生成一张主图、SKU、详情核对；失败或超时先核对原任务，不盲目重发。
