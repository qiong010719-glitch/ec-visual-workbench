## 行为变化

1. 用户仍手动标记原字中心、拖动新位置，再点“重绘这一张”。客户端单独提交完整原文和拖动点；不再用贴边夹紧后的大方框中心代替实际拖动点。
2. 服务端先用本机 Tesseract.js 识别原字查找范围。当前只接受唯一匹配、置信度至少 85 的单行原文；空格和全角标点规范化后比较，保留标点、字序和每个文字，不做近似纠错或子串匹配。识别失败、歧义、越界或新位置放不下整句时，在调用图片服务前停止。
3. 蒙版收紧到识别出的整句边界加 2–8 像素余量。新区域保留原句宽高，以用户拖动点为中心。没有采用逐笔画蒙版：模型笔画略有变化时，逐笔画硬裁存在截字风险。
4. 原图仍是输入图 1；输入图 2 是红蓝定位参考。沿用算舟、原有模型选择和 `/images/edits`，最终字形由模型绘制。没有前端文字图层、本地排字或把原字像素移贴进成图。
5. 返回后核对整句、大小、中心、旧位残字、参考标记和边界。中心容差为最大值 `3px` 或原句高度的 `10%`；宽高另有检查。通过后仅复制两条收紧区域，其他 RGBA 像素取原图，再核对实际合成结果的文字。任何检查失败都不替换原图。
6. 任务持久保存识别后的两个像素方框及原句。下载恢复使用保存的定位记录，不重新识别原图并计算另一张蒙版，也不再次生图。旧任务仍保留原有矩形保护流程。
7. 页面把旧大框标为“原字查找范围”和“新位置参考范围”，显示本机识别、结果核对两个阶段；提示单行支持、靠边拦截和失败保留原图。

中文识别数据和 WASM 随 npm 依赖安装，运行时不下载语言包、不访问云端 OCR、不写识别缓存。识别运行在独立 worker 内，30 秒超时覆盖库初始化和识别，成功、失败和超时均终止该 worker。首次安装或更新后运行 `npm ci`。参考：[Tesseract.js API](https://github.com/naptha/tesseract.js/blob/master/docs/api.md)、[本地安装说明](https://github.com/naptha/tesseract.js/blob/master/docs/local-installation.md)。
