# 电商视觉工作台 · 本地复刻

基于用户提供的 [AUPlus 站点](https://ec-image-hardcore-a-plus.vercel.app/) 的公开 HTML、CSS、JavaScript 和静态素材复刻。原版界面、五个页面、三种作图模式及其前端交互保留；另实现独立的本地服务和商品草稿箱。

## 亚马逊与 Temu 双入口（更新于 2026-11-05）

原亚马逊首页 `/` 及主副图、A+、THD、手机 A+ 流程保留，只新增 **Temu 做图入口** 链接。Temu 位于 `/temu`，独立保存当前商品、方案、图片与草稿，共用构思和生图服务。

Temu 支持单套及 **1–20 套裂变**，每套 1–7 张图片，可选 1:1（1024×1024）或 3:4（1152×1536）。已合入上游新版场景、镜头、字体、文案检查与构思通道改进。主图与详情同图同序，不另做 A+；各套独立确认方向、构思、生图，可刷新恢复、逐张重做和恢复下载。完整套图可导出带批次／套图编号的 `listing-manifest.json` 和独立草稿，保留上架母稿的 SKU 预览图规则，供后续上架流程对接；当前不发布商品。具体使用、尺寸处理和验收边界见 [Temu 工作流说明](docs/temu-workflow.md)。

双击 **启动Temu工作台.cmd** 可在独立的本机端口 4183 启动这份代码，避免占用已有亚马逊工作台的 4173 端口。该服务同时提供两个入口；原启动脚本仍使用原端口。

## 启动

Windows 双击 **启动工作台.cmd**，或在本目录运行：

```powershell
npm.cmd ci
npm.cmd start
```

打开 <http://127.0.0.1:4173/>。需要 Node.js 22 或更新版本；新增 `sharp` 依赖用于 Temu 图片尺寸规范与校验，首次启动先运行 `npm.cmd ci`。默认仅监听本机。现有上级目录的淘宝、抖店脚本及商品数据没有改动。

## 当前能用的功能

- 原版玻璃界面、壁纸、聚光、快捷键、模式介绍、样片、新手引导和图片预览。
- 快速、大师、极速三种模式的界面与输出范围；主副图、老 A+、高级 A+、THD、自定义数量及逐图要求。
- 产品资料、市场语言、人物、品类配额、信息密度、场景倾向、素材分类及上传。
- 生成可编辑的本地设计方案；可选接入独立文本模型。
- [亚马逊多套裂变](docs/多套裂变.md)：沿用上游 1–10 套功能；Temu 独立入口支持 1–20 套，两平台批次与草稿分别保存。
- 服务端任务队列、逐图进度、失败状态、刷新恢复、任务去重及本地测试点数退回。
- 图片生成与参考图编辑接口适配；局部编辑、产品替换、自由编辑、手机 A+ 重排的原版操作流程。
- 生图模型可选 GPT Image 2 或 GPT Image 2.5 Sunburst；每个任务保存所选模型并传给实际图片接口，失败不自动换模型。模型选择与大师/快速设计模式、视觉风格独立，刷新后保留。
- 原版智能分割、手动裁切、图片下载、ZIP 打包、评价和历史恢复。
- 新增本地商品草稿：SKU 编码、名称、价格、库存，保存、重新读取、编辑和导出 ZIP。资料包含 JSON、SKU CSV、设计方案和图片。
- 设计参考库：已有图片导入、Apify 美国站类目榜单采集、高清商品图/A+/品牌故事下载、实际视觉分析、逐图结果查看、参考选择和策划检索。
- 按槽位分离作图提示词；检索按主图、副图、A+ 角色匹配，相关性接近时优先参考不同品牌，避免整套图片重复使用完整 SOP。

## 图片服务

### 场景广告风格（2026-11-03 更新）

2026-11-04 更新为分镜版本 3：补充剂及通用商品按卖点混合人物环境、无人物微距、手部特写、俯拍图谱、信息版面与连续动作，逐图指定镜头和产品比例。“一张图”的整套主题要求分配给一个卖点图或 A+ 槽位，“每张图”的要求保留为通用要求，不再把整段要求重复广播到每个生图任务。原有方案和图片保留；新版需要重新构思后生成，不能只在旧方案上点重绘来套用新分镜。

在快速或大师设计中选择「场景广告风格 · 跨类目参考」，上传当前商品素材并填写真实卖点，再点击「一键构思」和生成。希望接近已确认的摄影样张时选择大师设计；快速模式仍分别遵循信息密度和场景倾向。可用自定义方案选择 1 张主图、6 张卖点图和 7 张 A+；默认套餐数量保持原样。

新策划按购买问题、可支持的事实、具体场景／动作／细节、产品在画面中的角色安排每张图。A+ 扩展情境、整体与局部关系、连续过程与选购信息；七个模块各有主题。墨镜、洗手液和保健品有对应的表达规则，其他商品使用用途与事实驱动的通用分镜。原有风格保留。旧版场景方案须重新构思，历史方案和图片不会删除；误删为空的单图方案会在提交生图前提示补齐。

无香说明不作为香调证据，香调不升级为配方，镜片颜色不升级为 UV 或偏光参数，补充剂成分不升级为疗效；明确儿童款按已提供人群策划。图片模型仍可能出现细小标识或结构差异，实际结果需要核对，不能保证每次或每个品类都与样张完全相同。验证与备份保存在 `runs/rich-style-integration-20261103/`。

只读取 `SUANZHOU_IMAGE_API_KEY`，不会回退到文本模型或模型供应商密钥。Windows 启动脚本会读取已安装双密钥配置中的用户环境变量；命令行启动读取进程环境或本目录 `.env`。

如需手动配置，将 `.env.example` 复制为 `.env`，填入专用密钥。不要提交 `.env` 或把密钥写入浏览器代码。

默认服务地址 `https://api.suanzhou.vip/v1`。`SUANZHOU_IMAGE_MODEL` 仅控制未指定模型时的默认值（当前为 `gpt-image-2`）；页面可选 `gpt-image-2` 和 `gpt-image-2.5-sunburst`，每次实际请求使用客户选择的模型。纯文本作图调用 `/images/generations`，含参考图的请求调用 `/images/edits`，以 multipart 发送图片。页面使用中性的“图片生成服务”名称，密钥环境变量保持兼容。

任务在排队时保存模型，成功与失败记录均保留；不支持的模型在扣测试点前拒绝，不自动换模型。上游若返回模型名，会保存为 `providerModel` 并核对型号，允许同型号的日期快照；明确不一致则失败。2026-11-03 已单次实测 Sunburst 参考图编辑，HTTP 200，返回型号为 `gpt-image-2.5-sunburst`，验证记录见 `reference/image-model-selection-20261103/live-result.json`。原服务需重启才加载新后端，页面应随之刷新；旧后端不会显示未接通的 Sunburst 选项。

已有历史任务记录包含算舟真实生图成功结果。当前参考库改造的自动化验收使用测试替身，没有额外生成图片；新的参考设计对成图质量的影响仍需后续实际作图检验。没有密钥时明确报错，不用样片冒充生成结果。参考图编辑端点不可用时任务失败，不会悄悄丢弃参考图改成纯文本生成。生图请求超时不自动重发，以免重复扣费。

生成结果下载支持独立的 `IMAGE_DOWNLOAD_PROXY` 配置，填写在 `.env`，例如 `http://127.0.0.1:15236`；代理功能需要 Node.js 24.5 或更新版本，当前电脑使用 25.6.0。代理软件需要保持运行，端口变化时修改此配置并重启工作台。该配置只用于生成结果下载，不更换图片 Key 或生图接口，也不修改系统代理。

网络错误会对同一结果地址最多下载 3 次，每次最多 90 秒，并检查图片是否完整。403 等过期／无权限结果不会自动反复重试。结果链接在下载前保存到本机任务记录；页面区分排队、生成和下载，失败时可点“重试下载”，也可从工作台的“恢复下载”查看记录。恢复下载不重新调用生图接口、不新增测试点扣款，连续点击会合并为同一次任务。较早失败任务若没有保存结果链接，无法自动补回；服务重启也不会重新提交生图。

图片尺寸暂映射到模型常用的 1024×1024、1536×1024、1024×1536；设计要求携带目标比例。21:9、16:9 等目标并非已验证的原生像素保证；原版手机图下载仍会规范为 1200×900。

## 构思方式与原站差异

2026-11-04 本地构思配置升级为 `PLANNER_MODEL=gpt-6.1-sol`。`PLANNER_REASONING_EFFORT` 留空，请求不附加 `reasoning_effort` 参数，使用服务商默认推理强度；等待时间配置为 10 分钟。该设置用于「一键构思」生成逐图设计方案，图片生成和图片分析仍使用各自的独立模型。已有方案需要重新构思才会使用新配置。

本机于 2026-11-01 将设计构思接入算舟 `gpt-5.6-luna`。`src/planner.mjs` 先整理输入资料、范围、语言、品类、逐图要求和参考库设计观察，再由模型生成可编辑的逐图方案，并检查要求的图片段落是否完整。该流程**不是原站私有多 Agent 提示词或 n8n 工作流**。

通过 `.env` 中的 `PLANNER_BASE_URL`、`PLANNER_API_KEY`、`PLANNER_MODEL` 配置兼容 Chat Completions 的文本模型。构思使用通用文本/视觉密钥，与专用生图密钥分开；缺少任一构思配置时使用本地规则。已实测接口返回模型为 `gpt-5.6-luna`，并完整生成主图和两张卖点图方案；验证记录保存在 `data/verification/planner-luna-20261101/`。

构思默认等待完整响应最多 5 分钟，可用 `PLANNER_TIMEOUT_MS` 调整（上限 10 分钟，当前配置为 10 分钟）。构思请求使用 Node 原生 HTTP/HTTPS，响应头等待与响应体读取均由同一个总时限控制，避免内置 fetch 的额外 300 秒响应头超时提前中断 Sol `max` 的长请求；服务商或底层网络仍可能提前中断。超时、HTTP 失败、响应截断和段落不完整会分别记录原因，不自动再次提交模型请求。标题允许常见 Markdown 标记、空格及全角数字；缺段、空段和重复段落仍拒绝作为完整方案。诊断信息保存在本机任务记录，已返回但不完整的文字保存在服务端 `partialPlanText` 字段，供排查而不直接进入生图。页面测试点数不等于真实模型账单。

## 设计参考库与 Apify

Apify 密钥填写在本机 `.env.apify` 的 `APIFY_API_TOKEN=` 后面，保存即生效。文件及所有 `.env.*` 凭据均排除在源码包之外。

视觉分析读取 `VISION_*`，其次是 `PLANNER_*`；均未配置时使用现有通用 `SUANZHOU_API_KEY` 与 `gpt-5.4-mini`。本机已独立配置 `VISION_BASE_URL`、`VISION_API_KEY`、`VISION_MODEL=gpt-5.4-mini`，避免切换构思模型时一并改变图片分析模型。视觉分析发送真实图片字节；专用 `SUANZHOU_IMAGE_API_KEY` 仅供作图服务使用。此次全店素材分析已实际调用视觉模型，逐图结果和进度保存在 `data/research/`。

“学习”指图片分析、设计规则整理及策划检索，没有微调模型权重，也没有取得原站私有后端。只有完整分析的资料组进入策划检索；参考图像不作为新商品的身份素材发给生图服务。`/api/research/design-patterns` 提供按图片角色整理的设计特征及证据哈希。

首批范围为美国站充电宝；品牌排序是榜单样本内的推算，不是 Amazon 官方品牌销售榜。图片和排名缺口如实保留，颜色变体按采集到的变体关系去重。每次采集需要明确费用上限，视觉模型费用另计。详细规则与入口见 [设计参考库说明](docs/设计参考库.md)。店铺装修素材支持分析与查看，装修图生成功能暂未制作。

多类目扩展记录保存在 `data/research/amazon-expansion-20261101/`。工作台支持按类目筛选和查看分支进度；同一商品可保留多个类目的排名证据。扩类采集台账把此前已用费用、运行中的最大费用和已结束运行的实际费用合并计算；刚结束但账单尚未稳定的运行继续预留费用上限，并在下次采集前重新核对。用户已将累计上限提高到 15 美元，本轮核对累计 $11.7380，剩余 $3.2620。`collection-pause.json` 记录当前采集阶段已结束，剩余额度可供后续补采使用。

前一轮 2026-11-01 3C 续采新增 83 条商品资料及 1,844 张独立图片分析，已接入后端。扩类活动累计 187 条 ASIN 记录、3,743 张独立图片；包含原有店铺资料的全库为 272 组资料、5,472 张独立图片。17 个 Electronics 一级实物分支都有参考，只有耳机已达到 5 个品牌各 5 款；其他款数、更细子类和其他大类仍有缺口。详情见 [美国站 3C 扩类学习记录](docs/美国站3C扩类学习-20261101.md)。

该批依次使用 `tools/capture-amazon-expansion.mjs`（已有浏览器会话读取公开榜单）、`tools/rank-amazon-expansion.mjs`（Apify 榜单）、`tools/collect-amazon-expansion.mjs`（核实候选及筛选品牌）、`tools/learn-amazon-expansion.mjs download|analyze`（下载及真实视觉分析）和 `tools/merge-amazon-expansion.mjs`（校验完成后合入参考库）。不要为了恢复进度重复发起付费采集；先检查费用台账、已有运行及暂停记录。

完成合并并重启本地服务后，`node tools/verify-expansion-integration.mjs` 只读检查本批逐图结果、文件哈希、在线统计和实际参考策划，不调用模型或生成图片。检索已补充“车载手机支架”和“手机钢化保护膜”与英文商品标题的匹配；明确选择的参考仍优先使用。

新增设计观察用于新建或重新构思的常规主图、副图和 A+ 策划，已保存的旧方案不会自动改写。采集文件包含小尺寸比较卡和组件图，不全是高清主视觉；实际出图质量仍需另行验证。

## 数据与草稿

- 服务端：`data/workbench.json` 存任务、批次、反馈和草稿；`data/media/` 存上传与生成图片。
- 设计资料：`data/research/references.json` 存参考库、分析缓存和采集记录；原始数据集与店铺归档保留在对应子目录。目录含实际资料，不随源码包发布。
- 浏览器：原版 IndexedDB/localStorage 保存当前工作台和历史结果；同一域名/端口刷新可恢复。
- `tests/results/` 为验收截图、报告和测试 ZIP，不能作为真实生成质量证据。
- 服务重启后，结果不明的进行中任务标记失败，不自动重复下单。
- 草稿只在本机保存，**不是已经写进淘宝或抖店草稿箱**。目前通过资料包衔接已有上架流程；没有自动调用店铺脚本，也没有发布接口。
